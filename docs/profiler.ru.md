# Symfony Profiler

Когда приложение работает с `kernel.debug: true` и включённым `WebProfilerBundle`, бандл добавляет пункт **JSON-RPC** в Symfony toolbar и profiler.

Панель содержит два представления:

- **Calls** показывает входящие вызовы текущего HTTP-запроса: метод, JSON-RPC id, замаскированные параметры и ответ, статус result/error, код ошибки, длительность и context id логирования. JSON-RPC batch отображается одной строкой с дочерними вызовами.
- **Registered methods** читает скомпилированные спецификации методов бандла. Для каждой версии и метода показываются handler, Request DTO, параметры и их обязательность, summary, tags, group и roles.

Дополнительная конфигурация не нужна. Сбор для profiler не зависит от `logging.enabled`: отключение PSR-3 логов не оставляет dev-панель пустой. Traceable-логгер декорирует настроенный call logger, поэтому при включённых логах сохраняются те же записи и context id.

## Чувствительные значения

Данные запросов и ответов проходят через тот же настроенный `SensitiveDataMasker`, что и call logging. Стандартные шаблоны скрывают пароли, токены, секреты и похожие значения. Загруженный файл представлен только исходным именем, размером и MIME-типом; содержимое файла и временный путь никогда не сохраняются.

Для неразбираемого сырого body сохраняется только размер в байтах, но не содержимое.

## Доступность и стоимость

Сервисы traceable-логгера и data collector существуют только при двух условиях:

1. Включён `kernel.debug`.
2. Зарегистрирован `WebProfilerBundle`.

В остальных случаях они удаляются из контейнера, поэтому production-запросы не несут стоимости сбора. Сейчас profiler записывает только входящие вызовы; исходящий JSON-RPC трафик не входит в scope.
